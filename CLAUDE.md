## Project Overview

PharmCAT (Pharmacogenomics Clinical Annotation Tool) is a bioinformatics tool that analyzes genetic variants to predict drug response and tailor medical treatment to individual patient genetic profiles. It operates in two phases:

1. **Named Allele Matching**: Processes VCF files from NGS/genotyping and identifies pharmacogenomic genotypes, inferring haplotypes (star alleles)
2. **Phenotyping & Reporting**: Uses pharmacogene diplotypes to predict PGx phenotypes and generates drug-prescribing recommendations from CPIC guidelines, DPWG guidelines, and FDA-approved drug labels

This branch (`chinese-translation`) tracks upstream PharmCAT and translates the prescribing
guidance into Chinese. It is currently merged up to upstream **v3.4.0**.

PharmCAT uses Gradle as its build system. Key commands:

### Build & Test
```bash
./gradlew clean          # Clean build artifacts
./gradlew build          # Full build with tests
./gradlew test           # Run all tests (JUnit)
```

```bash

./gradlew test

# Run specific test class
```

```bash

java -jar build/libs/pharmcat-*-all.jar -vcf <input.vcf>
```

## Architecture

PharmCAT is structured as a modular pipeline with three main phases:

### 1. Named Allele Matcher (`org.pharmgkb.pharmcat.haplotype`)
- **Entry Point**: [NamedAlleleMatcher.java](src/main/java/org/pharmgkb/pharmcat/haplotype/NamedAlleleMatcher.java)
- Reads VCF files and matches variants to named alleles (star alleles)
- Uses gene definition files from `src/main/resources/org/pharmgkb/pharmcat/definition/alleles/`
- Outputs diplotype matches in JSON format
- Special handling for complex genes like CYP2D6 (structural variants, hybrid alleles)

Key classes:
- `NamedAlleleMatcher`: Main matching logic
- `VcfReader`: Parses VCF files
- `SampleAllele`: Represents patient alleles
- `DiplotypeMatch`: Represents matched diplotype pairs

### 2. Phenotyper (`org.pharmgkb.pharmcat.phenotype`)
- **Entry Point**: [Phenotyper.java](src/main/java/org/pharmgkb/pharmcat/phenotype/Phenotyper.java)
- Takes diplotype calls from matcher (or outside calls)
- Translates diplotypes to phenotypes using phenotype translation tables
- Handles activity score calculations
- Outputs `GeneReport` objects with phenotype assignments

Key classes:
- `Phenotyper`: Main phenotyping logic
- `OutsideCall`: Handles manually provided diplotype calls
- Phenotype data in `src/main/resources/org/pharmgkb/pharmcat/phenotype/`

### 3. Reporter (`org.pharmgkb.pharmcat.reporter`)
- **Entry Point**: [ReportContext.java](src/main/java/org/pharmgkb/pharmcat/reporter/ReportContext.java)
- Generates clinical reports from phenotype data
- Matches phenotypes to drug recommendations from CPIC, DPWG, and FDA
- Outputs HTML and JSON reports
- Uses Handlebars templates for HTML generation

Key classes:
- `ReportContext`: Main reporting orchestrator
- `PgkbGuidelineCollection`: Loads prescribing guidance
- `DiplotypeFactory`: Creates diplotype annotations
- HTML template: `src/main/resources/org/pharmgkb/pharmcat/reporter/report.hbs`

### 4. Definition Reader (`org.pharmgkb.pharmcat.definition`)
- **Entry Point**: [DefinitionReader.java](src/main/java/org/pharmgkb/pharmcat/definition/DefinitionReader.java)
- Loads gene allele definitions from JSON files
- Provides reference allele information
- Handles gene-specific exemptions and special cases

### Pipeline Integration
- **Entry Point**: [PharmCAT.java](src/main/java/org/pharmgkb/pharmcat/PharmCAT.java)
- Orchestrates the full pipeline from VCF to final report
- Handles command-line arguments and file I/O
- Can run components independently or as full pipeline

## Chinese Translation Feature

The translation is **data-only** — no Java or template changes are required.

### How it works
`src/main/resources/org/pharmgkb/pharmcat/reporter/prescribing_guidance.json` is upstream's
file with exactly two fields translated in place, for every recommendation:

- `recommendations[].text.html`
- `recommendations[].implications[]`

Everything else (ids, lookup keys, genotypes, drug names, structure) is byte-identical to
upstream. `prescribing_guidance.v3.4.0.json` sits alongside it as the untranslated English
reference for the current data version — diff it against the next upstream release to find
what needs re-translating.

Conventions to preserve when editing translations:
- Keep HTML tags and `id="..."` anchors intact; translate only the visible text.
- Keep entities as-is (`&quot;` `&gt;` `&le;`) — both fields render via `{{{ }}}` (raw HTML).
- Keep gene symbols, star alleles, rsIDs, PMIDs, doses and units in the original form.
- Implications keep their `GENE: ` prefix in English.

### No fork-specific Java path
All legacy Chinese Java/model/template changes were removed. `src/main/java/` and
`report.hbs` must remain identical to upstream for this release; the translated guidance
resource is the only runtime difference.

### Building with Chinese Translation
```bash
python3 src/scripts/translation/verify.py
python3 -m unittest discover -s src/test/python/translation -p 'test_*.py' -v
./gradlew clean test shadowJar
```

GenDecoder creates the production bilingual Singularity image with its own pinned

### Canonical terminology
Core terms use 慢代谢者 / 中间代谢者 / 正常代谢者 / 快代谢者 / 超快代谢者,
活性评分, and 参考型. Deprecated aliases are enforced by `pgcore.CANONICAL`; structured
CSV-field terms are maintained in GenDecoder and checked across both layers.

## Important Data Files

### Gene Definitions
Located in `src/main/resources/org/pharmgkb/pharmcat/definition/alleles/`:
- 21 gene definition files (e.g., `CYP2D6_translation.json`, `TPMT_translation.json`)
- Define variant positions, allele combinations, and function assignments
- Updated via `./gradlew updateData`

### Prescribing Guidance
- `src/main/resources/org/pharmgkb/pharmcat/reporter/prescribing_guidance.json`
- Contains CPIC, DPWG, and FDA drug recommendations
- Structured as: Gene → Drug → Phenotype → Recommendation

### Phenotype Definitions
Located in `src/main/resources/org/pharmgkb/pharmcat/phenotype/`:
- Maps diplotypes to phenotypes
- Defines activity scores
- Gene-specific phenotyping rules

## Special Gene Handling

### CYP2D6
- Most complex gene due to structural variants (deletions, duplications, hybrids)
- Special scripts in `src/scripts/cyp2d6/`
- Requires careful handling of copy number variations
- Can be called by external tools (see Outside Call Format)

### G6PD, CACNA1S, RYR1
- X-linked or special inheritance patterns
- May require outside calls for accurate results

### Research Mode
Enable experimental features:

```bash
java -jar pharmcat.jar -vcf input.vcf -research cyp2d6,combinations
```

## Outside Call Format

PharmCAT accepts external diplotype calls via TSV files (`-po` option):
```tsv
#gene	diplotype	phenotype	activityScore
CYP2D6	*1/*4	Intermediate Metabolizer	1.0
HLA-B	*15:02/*58:01	*15:02 positive
```

This is essential for:
- Genes not called by PharmCAT's matcher
- External tools with better calling for specific genes (e.g., CYP2D6)
- Manual override of PharmCAT's calls

## Key Conventions

1. **Null Safety**: Use `@Nullable` annotations; prefer `Optional` where appropriate
2. **Immutability**: Prefer immutable collections (Guava's `ImmutableMap`, etc.)
3. **Gene Names**: Always uppercase (e.g., `CYP2D6`, not `cyp2d6`)
4. **Star Alleles**: Format as `*1`, `*2`, etc. (not `star1` or `1`)
5. **Activity Scores**: Floating-point values representing enzyme function
6. **Error Handling**: Use `ReportableException` for user-facing errors

## VCF Requirements

PharmCAT has specific VCF requirements:
- Must be normalized (left-aligned, decomposed multi-allelics)
- Positions must be on GRCh38 (hg38) reference
- Use VCF Preprocessor for best results: `pharmcat_vcf_preprocessor`
- Missing genotypes can be treated as reference with `--missing-to-ref` flag
